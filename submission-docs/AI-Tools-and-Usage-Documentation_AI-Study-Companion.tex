\subsection{How I worked with the agent (my actual loop)}

\begin{enumerate}
\item \textbf{One prompt at a time, in build order.} I pasted
\texttt{architecture.md} once as context, then fed one phase prompt, waited for green
acceptance checks, and only then moved on.
\item \textbf{Acceptance checks were real commands} --- \texttt{npm test} (314 passing),
\texttt{npm run eval} (18/18 fixtures), \texttt{npm run build / lint / typecheck},
plus live Supabase queries. Outputs were recorded into phase logs and
\texttt{evaluation.md}, not hypothesised.
\item \textbf{/compact between phases.} Each phase ended with a context compaction; I saved
the exact prompt + result + deviations into \texttt{development-prompts/NN-name.md}.
That folder is the raw history; the ``AI Prompts'' document is its cleaned, organised companion.
\item \textbf{I stayed the reviewer.} I kept, cut or rewrote agent output --- e.g.\ I rejected
an over-generic recommendation prompt and replaced it with one that bans ``keep studying''
and forces named concepts; I simplified mastery to the explainable 0.7/0.3 formula rather
than the agent's heavier first draft.
\end{enumerate}

\begin{shaded}
\noindent\textbf{What AI did NOT do (so expectations stay honest):}
it did not create my Supabase / Vercel / Inngest accounts, did not set production env vars,
did not run the live-URL smoke test (signup $\rightarrow$ space/project $\rightarrow$ PDF
$\rightarrow$ READY $\rightarrow$ Tutor $\rightarrow$ quiz $\rightarrow$ mastery/growth/recommendations
--- manual), and did not record the demo video.
Any gap between ``passes locally'' and ``works live'' was closed by me, by hand, on the deployed URL.

\section{Part B --- AI used BY the final product}

All runtime AI flows through one thin abstraction --- \texttt{lib/ai/AIService.ts} ---
so providers can change without touching features. Current split:

\begin{description}[leftmargin=1.2cm,style=nextline]
\item[Chat / structured / evaluation $\rightarrow$ Mercury]
\texttt{mercury-2.5} (\texttt{https://api.inceptionlabs.ai/v1}).
JSON mode + per-feature validators; reasoning-model shaping
(token headroom, temp clamp [0.5,1], \texttt{reasoning\_effort=low} for structured tasks); 90\,s timeout.
\item[Embeddings $\rightarrow$ Google Gemini]
\texttt{gemini-embedding-2}, 768 dims (\texttt{chunks.embedding VECTOR(768)}, migration 012).
Same model + config for documents (\texttt{title | text}) and queries
(\texttt{task: search result | query}); key server-only; 10-minute query cache.
\end{description}

\subsection{Cost, latency \& debuggability}

Every call writes \texttt{ai\_operations(feature, model, request\_id, latency\_ms, success, tokens, estimated\_cost, error)}, surfaced in \texttt{/admin/ai-usage} and project/global analytics. Cost is controlled structurally: embeddings only for real work (processing batches + uncached queries --- never on page open, never re-indexing READY material), per-user rate windows (tutor 20/min, quiz-gen 5/min, quiz-submit 60/min, and others $\rightarrow$ 429 + Retry-After), and conversation prompts bounded by the 6-message window + summary. An on-call question like \textit{``why was that Tutor answer slow / which model / why poor retrieval / which workflow failed / what did it cost?''} is answerable from one table join.

(Honest note: provider \texttt{usage} objects are not yet threaded into every row, so token/cost cells can be null --- calls, latency and errors are complete; cost capture is queued next.)

\subsection{Safety posture (runtime)}

\begin{itemize}
\item \textbf{Isolation:} retrieval, conversations, chunks, quizzes and recommendations are all project-ownership-gated; cross-project reads return 404.
\item \textbf{Injection:} Tutor / practice / concept prompts delimit retrieved text as untrusted; remaining generators are queued for the same treatment.
\item \textbf{Validation:} no raw LLM text is persisted --- every feature has a server-side schema check; hallucinations (e.g.\ fake chunk IDs) are dropped and groundedness downgraded.
\item \textbf{Secrets:} Mercury + Gemini keys are server-only env vars; the browser never sees them.
\end{itemize}

\subsection{Evaluation linkage}

Runtime quality is checked by 18 curated fixtures (grounded / unsupported / multi-concept / citation / injection; retrieval relevance; grading quality; recommendation actionability) via \texttt{npm run eval}, with run-over-run \texttt{IMPROVED / REGRESSED / UNCHANGED / BASELINE} tracking in \texttt{/admin/ai-evaluation} --- so a prompt, model or retrieval change that regresses behaviour is caught, not silently shipped.

\medskip
\noindent\textit{Bottom line: Part A made a 3--4 day prototype feasible; Part B is what is actually being graded --- a small set of well-guarded model calls wrapped in deterministic learning logic, full observability, and an eval harness. The model could be swapped tomorrow; the architecture would not need to change.}
